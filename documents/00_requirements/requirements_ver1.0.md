# 要件定義_ver1.0

## 本書の位置づけについて

本書は minecraft-pixelart の **Ver1.0 の正本**である。プロダクトの目的・機能の要否・線引きを書く。未決は `issue_list.md`。コードの正本ではない。確定した仕様だけを載せる。

## Ver1.0 凍結

2026-08-27 に凍結。簡単なテスト済。実装レビューでブロッカーなし。v1.1 は作らない。

## 概要

画像を Minecraft のブロック配置に変換し、データパックとして書き出す配布用 CLI。個人の単発スクリプト `pixel-art.py` を、他人が使える配布物にする。

対象は **Java Edition 26.2**。自分のワールドにドット絵を置きたいプレイヤー向け。Mod 必須にはしない。v1 では 26.2 以外のバージョンを同梱しない。

配布の形は GitHub 上の PEP 723 スクリプト（`uv run` 等）。pip パッケージは後。README の pip-tools テンプレはこれに合わせる。

## Ver1.0 で作るもの

- 画像ファイルを入力する配布用 CLI（PEP 723）
- 入力画像のピクセル数は問わない。指定されたブロック数（幅・高さ）へ LANCZOS で縮小してから、各セルの色をパレットへ写す。種の `240×300` ハードコードは採用しない
- 色の近いブロックを選ぶ（いまの `pixel-art.py` と同じ距離。いわゆる redmean）。ディザはしない
- 絵の横方向の連続を `/fill` に圧縮する
- 相対座標または絶対座標
- 回転（0/90/180/270）と左右反転
- 配置の向きは地面に平行（床）でも垂直（壁）でも出せる。壁は南・北・東・西の 4 つ（南北は XY の両方、東西は ZY の両方）。`north` はエラーにしない
- プレビュー画像（割当後のブロック色）
- Minecraft データパック。`pack.mcmeta` を含み、`function` と `functions` の両方へビルド用 `.mcfunction` を置く（種と同じ両書き）

## Ver1.0 で作らないもの

- Litematic / schematic / ワールド直接書き込み（Litematic は後）
- サーバーへ置く Web UI
- pip パッケージ（後）
- 複数バージョンのパレットやデータパック同梱（当面 26.2 のみ）
- Bedrock Edition
- 有料アセットや非公式リソースパック前提の色
- 生存向けの追加フィルタ（鉱石を使わない、など）。後回し
- ディザ（v2）
- 自動テストスイート（`tests/` は v1 では無い）

## 変換の流れ（v1）

1. 入力画像を読む。完全透明（アルファ 0）の画素は空気。それ以外は不透明化して扱う
2. 指定のブロック幅・高さへ LANCZOS で縮小する
3. 回転・左右反転する
4. 各セルの色に最も近いパレットブロックを選ぶ（空気セルはスキップ）
5. 絵の横方向のランを `/fill`（長さ 1 なら `setblock`）に圧縮する。空気は置かない
6. 指定の向き（床または壁）と相対/絶対で座標を振る
7. 割当後のブロック色でプレビュー画像を書き、データパックを書き出す

## 配置

原点（相対の実行位置 / 絶対の開始座標）:

- **床**: 絵の左上
- **壁**: 絵の左下（足元から正立）

向き:

- **床**: 地面に平行。XZ 平面、Y は一段。絵の横 → X、絵の縦 → Z（上端が北）
- **壁・南向き（XY）**: 垂直。絵の左→右が +X。正面未指定のときの既定
- **壁・北向き（XY）**: 南の左右反転。絵の左→右が -X。v1 で出す。`north` はエラーにしない
- **壁・東向き（ZY）**: 絵の左→右が -Z
- **壁・西向き（ZY）**: 絵の左→右が +Z

相対の床は `~dx ~ ~dz`。壁・南北は `~dx ~dy ~`。東西は `~ ~dy ~dz`。絶対は開始座標に加算する。

`fill` / `setblock` の相対は、オフセット 0 を `~`（`~0` と書かない）、負を `~-N`（空白なし）とする。既存ブロックを上書きする。確認プロンプトは必須にしない。

## パレット

ブロック色は Python に埋め込まない。v1 の同梱パレットは種由来の約 113 色（`data/palette/palette_26.2.json`、対象ラベルは 26.2）。jar から全ブロックを再生成するツールはメンテナ用。許可リスト無しで再生成すると、規則に無い ID（コンクリート含む）が `functional` 扱いで既定から落ちうる。利用者は同梱 JSON を使う。

平均色は **side** テクスチャの **不透明画素のみ**。草ブロックも side。

**既定パレットから外す**

- 液体（水・溶岩・粉末雪など）
- 機能ブロック（レッドストーン機器、コンテナ、作業台系、TNT、スポナー、ベッド、ポータル、コマンド系など。置くと動きやインベントリに副作用があるもの）
- 非フルキューブ（半ブロック、階段、柵、板ガラス、カーペット、ドアなど）
- 氷（氷塊・青氷を含む）、スライム、ハチミツ、葉

**既定パレットに入れる（#3 の例外）**

- ガラス、色付きガラス

**落下ブロック（砂・赤い砂・砂利・コンクリートパウダー）**

置いた下に空間があると落ちて絵が崩れる。使うかどうかは利用者が決める。CLI で未指定なら実行時に尋ねる。尋ねられない場面（非対話）では使わない。

生存向けの追加フィルタは v1 では出さない。

## データパック

v1 の成果物は、ワールドの `datapacks/` に入れて使えるパックである。

- `pack.mcmeta` を必ず書く（種は未出力。v1 では必須）
- `min_format` は `[101, 1]`、`max_format` は `120`。26.2 の 107.1 はこの範囲内。全バージョン共通の pack ではない。古い整数の `pack_format` は書かない
- 未指定のパック名 / 名前空間は入力画像の stem を `[a-z0-9_.-]` に sanitize した値。エントリ関数の既定は `build`。実行は `/function <stem>:build`。指定すれば変えられる。`pixelart` 固定はやめる
- コマンドは 65000 行でファイル分割し、エントリから順に呼ぶ。1 ファイルに黙って切り捨てない
- `function` と `functions` の両方へ書く
- `load.json` / `tick.json` は置かない。利用者が `/function` する
- 文字コードは UTF-8、改行は LF（種と同じ）

## CLI の入力

必須: 入力画像、出力するブロック幅と高さ。

任意と既定:

- 配置の向き: **未指定なら実行時に尋ねる**（壁・南 / 壁・北 / 壁・東 / 壁・西 / 床）。尋ねられない場面では壁・南向き（XY）。`--facing` のみ指定したときは尋ねず、壁 + その正面。`--orientation wall` だけで正面未指定のときは正面を尋ねる（既定は南）
- 落下ブロックを使うか: **未指定なら実行時に尋ねる**。尋ねられない場面では使わない
- 回転: 0
- 左右反転: なし
- 座標: 相対
- データパック名 / 名前空間: 入力画像の stem を sanitize（`[a-z0-9_.-]`。空なら `pixelart_<hash>`）。指定すれば変えられる
- 関数名: `build`
- プレビュー: `<out>/previews/<画像名>.png`

配置の向きと落下ブロックだけを尋ねるのは、データパックが座標と向きを焼き込むためである。litematic のように貼るときに位置や回転を選び直せず、落下も置いた時点で決まる。出力してから直せない選択に限って確認する。他の項目は黙って既定を採る。

質問を出さずに既定で通す指定（`--yes` 相当）を用意する。パイプやリダイレクト、スクリプトからの実行では尋ねない。

絶対座標を使うときは開始座標が要る。種の `ROTATION=90` や `240×300` は単発利用の値であり、配布 CLI の既定にはしない。
