# 要件定義_ver1.0

## 本書の位置づけについて

本書は minecraft-pixelart の **Ver1.0 の正本**である。プロダクトの目的・機能の要否・線引きを書く。未決は `issue_list.md`。コードの正本ではない。確定した仕様だけを載せる。

## 概要

画像を Minecraft のブロック配置に変換し、データパックとして書き出す配布用 CLI。個人の単発スクリプト `pixel-art.py` を、他人が使える配布物にする。

対象ユーザーは、自分のワールドにドット絵を置きたい Java Edition のプレイヤー。Mod 必須にはしない。

## Ver1.0 で作るもの

- 画像ファイルを入力する配布用 CLI
- 入力画像のピクセル数は問わない。指定されたブロック数（幅・高さ）へ縮小してから、各セルの色をパレットへ写す。種の `240×300` ハードコードは採用しない
- 色の近いブロックを選ぶ（いまの `pixel-art.py` と同じ距離。いわゆる redmean）
- 絵の横方向の連続を `/fill` に圧縮する
- 相対座標または絶対座標
- 回転（0/90/180/270）と左右反転
- 配置の向きは地面に平行（床）でも垂直（壁）でも出せる。一方に固定しない
- プレビュー画像の書き出し
- Minecraft データパック。`pack.mcmeta` を含み、`function` と `functions` の両方へビルド用 `.mcfunction` を置く（種と同じ両書き）

## Ver1.0 で作らないもの

- Litematic / schematic / ワールド直接書き込み（Litematic は後）
- サーバーへ置く Web UI
- Bedrock Edition
- 有料アセットや非公式リソースパック前提の色
- 生存向けの追加フィルタ（鉱石を使わない、など）。後回し
- ディザ（未決。提案は issue_list #4）

## 変換の流れ（v1）

1. 入力画像を読み、指定のブロック幅・高さへ縮小する
2. 回転・左右反転する
3. 各セルの色に最も近いパレットブロックを選ぶ
4. 絵の横方向のランを `/fill`（長さ1なら `setblock`）に圧縮する
5. 指定の向き（床または壁）と相対/絶対で座標を振る
6. プレビュー画像とデータパックを書き出す

縮小のアルゴリズム（セル中心の1点か、面積平均か）は未決。種はセル中心の1点サンプル。

## 配置

- **床**: 地面に平行。種と同じく XZ 平面、Y は一段。
- **壁**: 垂直。正面の軸（南北面 / 東西面）と相対座標の振り方は issue_list。
- 相対モードの床は種どおり `~dx ~ ~dz`（実行位置が原点。Y オフセットは 0）。絶対モードは開始座標に加算する。壁の相対/絶対の座標の振り方は issue_list。

`fill` / `setblock` は既存ブロックを上書きする。確認プロンプトは必須にしない。

## パレット

ブロック色は Python に埋め込まない。Minecraft の client jar からブロックテクスチャの平均色を生成し、バージョン付きデータとして持つ。新しいブロックは jar を差し替えれば足せる。

配布物には、生成済みパレットを同梱する（利用者が毎回 jar を用意しなくてよい）。jar からの再生成はメンテナ向け。

**既定パレットから外す（確定）**

- 液体（水・溶岩・粉末雪など）
- 機能ブロック（レッドストーン機器、コンテナ、作業台系、TNT、スポナー、ベッド、ポータル、コマンド系など。置くと動きやインベントリに副作用があるもの）
- 非フルキューブ（半ブロック、階段、柵、板ガラス、カーペット、ドアなど）

生存向けの追加フィルタは v1 では出さない。

透明なフルキューブ（ガラス・氷など）、葉、発光ブロック、草ブロックのどの面を平均するかは未決（issue_list）。

## データパック

v1 の成果物は、ワールドの `datapacks/` に入れて使えるパックである。

- `pack.mcmeta` を必ず書く（種は未出力。v1 では必須）。`pack_format` の値は未決
- 名前空間とエントリ関数で `/function` から実行できる
- コマンド数がゲームのチェーン上限を超えうる（種の規模でも 65536 を超えうる）。1 ファイルに黙って切り捨てず、分割してエントリから順に呼ぶ
- 文字コードは UTF-8、改行は LF（種と同じ）

## CLI の入力

必須: 入力画像、出力するブロック幅と高さ。床と壁はどちらも出せること。向きの未指定時の既定は issue_list。

任意: 回転、反転、相対/絶対、開始座標、データパック名、パレット/フィルタ、壁の正面、出力先。フラグ名と未指定時の既定は issue_list。種の `ROTATION=90` や `240×300` は単発利用の値であり、配布 CLI の既定にはしない。
